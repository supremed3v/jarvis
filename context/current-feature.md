- 2026-08-01 SPEC-0007 Go Runtime Bootstrap — Completed. Implemented services/core (new Go module, module jarvis-pa/services/core, go 1.23) as the Runtime lifecycle owner for the Core Runtime component. Added root go.work (joining packages/config, packages/errors, packages/logger, packages/shared-types, services/core) — the root-level workspace anticipated since SPEC-0001's note that "no root-level go.mod/go.work exists until SPEC-0007 Go Runtime Bootstrap ties the modules together" — so Runtime can import the Foundation packages directly without publishing them or hand-written replace directives. Runtime (runtime.go) exposes New(opts...)/State()/Start(ctx)/Shutdown(ctx)/Run(ctx): Start loads config via packages/config.Load (file + env layering, unchanged), parses the resulting log level via packages/logger.ParseLevel and constructs a component-scoped Logger, then initializes each registered Dependency (a minimal Name/Init/Close interface satisfying the "Dependency initialization" requirement) in order — on any failure it rolls back the already-initialized subset in reverse order, transitions to StateFailed, and returns a packages/errors-wrapped error carrying the failing dependency's name as Context. Shutdown tears down the running dependency set in reverse order, collecting (rather than stopping at) every Close error so one broken dependency can't block the others from releasing resources, and only succeeds from StateRunning. Run composes Start with a caller-supplied context so OS signal handling (signal.NotifyContext) stays out of the library and in a future cmd/ entrypoint. State machine: NOT_STARTED -> STARTING -> RUNNING -> STOPPING -> STOPPED, with FAILED on any Start error; STOPPED may Start again (restart supported). `go build ./...`, `go vet ./...`, `gofmt -l .` clean; `go test ./... -v` 13/13 tests pass at 100.0% statement coverage, covering clean startup/shutdown, dependency init ordering, rollback-on-failure, invalid config file, invalid log level, double-start rejection, restart-after-shutdown, best-effort multi-error shutdown, context-driven Run (including Run's own Start-failure path), and the packages/config env-override integration boundary (LOG_LEVEL). Re-verified all 5 workspace modules build/test clean under the new go.work — no regressions in the standalone Foundation packages. `go test -race` unavailable in this environment (CGO_ENABLED requires cgo, no C toolchain present), same constraint noted under SPEC-0005. Built on feature/go-runtime-bootstrap, merged into master. Full rationale: see docs/agents/JARVIS_BUILD_TRACKER.md (SPEC-0007 row).

- 2026-08-01 SPEC-0004 Shared Types Package — Completed. Implemented packages/shared-types (standalone Go module, module jarvis-pa/packages/shared-types, go 1.23, stdlib-only, no go.sum), following the packages/config (SPEC-0003) precedent for Foundation-layer packages. Defines four framework-independent, serializable data contracts with no business logic: Event (id/type/source/timestamp/payload), Task (id/type/status via TaskStatus enum/input/result/error/timestamps), Agent (id/name/type/status via AgentStatus enum/capabilities), Tool (name/description/parameters/permissions).
