  SPEC-0007   Completed         services/core: new Go module (module jarvis-pa/services/core, go 1.23) implementing the Runtime lifecycle owner for the Core Runtime component. Added root go.work (joining packages/config, packages/errors, packages/logger, packages/shared-types, services/core) — the root-level workspace anticipated since SPEC-0001's note that "no root-level go.mod/go.work exists until SPEC-0007 Go Runtime Bootstrap ties the modules together" — so Runtime can import the Foundation packages directly without publishing them or hand-writing replace directives. Runtime (runtime.go) exposes New(opts...)/State()/Start(ctx)/Shutdown(ctx)/Run(ctx): Start loads config via packages/config.Load (file + env layering, unchanged), parses the resulting log level via packages/logger.ParseLevel and constructs a component-scoped Logger, then initializes each registered Dependency (a minimal Name/Init/Close interface satisfying the "Dependency initialization" requirement) in order — on any failure it rolls back the already-initialized subset in reverse order, transitions to StateFailed, and returns a packages/errors-wrapped error carrying the failing dependency's name as Context. Shutdown tears down the running dependency set in reverse order, collecting (rather than stopping at) every Close error so one broken dependency can't block the others from releasing resources, and only succeeds from StateRunning. Run composes Start with a caller-supplied context so OS signal handling (signal.NotifyContext) stays out of the library and in a future cmd/ entrypoint. State machine: NOT_STARTED -> STARTING -> RUNNING -> STOPPING -> STOPPED, with FAILED on any Start error; STOPPED may Start again (restart supported). `go build ./...`, `go vet ./...`, `gofmt -l .` clean; `go test ./... -v` 13/13 tests pass at 100.0% statement coverage, covering clean startup/shutdown, dependency init ordering, rollback-on-failure, invalid config file, invalid log level, double-start rejection, restart-after-shutdown, best-effort multi-error shutdown, context-driven Run (including Run's own Start-failure path), and the packages/config env-override integration boundary (LOG_LEVEL).   SPEC-0009   Completed         services/core/eventbus.go: Bus, the concrete implementation filling the Container.EventBus slot SPEC-0008 reserved as a placeholder `interface{}`. EventBus interface exposes Publish(event) and Subscribe(eventType, handler) (unsubscribe func()); Bus delivers to each subscriber on that subscriber's own dedicated goroutine reading off a bounded buffered channel (default 64, overridable via WithSubscriberBufferSize), so Publish itself never blocks — a full subscriber buffer drops that subscriber's copy of the event (and logs a warning if WithBusLogger is set) rather than stalling the publisher or other subscribers. Handler invocation is wrapped in a recover() (deliver()) so one panicking subscriber can't take down its goroutine or the process. Close(ctx) stops every subscription's delivery goroutine and waits for them to drain (or ctx to be done, whichever first), returning a packages/errors-wrapped EVENTBUS_CLOSE_INCOMPLETE error (Type TIMEOUT or CANCELED depending on ctx.Err()) on the latter, consistent with runtime.go's error-wrapping convention; Close and unsubscribe are both idempotent (sync.Once-guarded) and safe for concurrent use. Bus also implements Name()/Init() alongside Close() so it optionally satisfies runtime.Dependency for ordered startup/shutdown via WithDependencies, without EventBus itself requiring that — this is additive, runtime.go was not modified. Defines the three example EventTypes named in the spec (EventUserMessageReceived, EventAgentStarted, EventTaskCompleted), fulfilling the SPEC-0004 note that concrete event names belong to "future services (SPEC-0009 Event Bus onward)". container.go's placeholder `type EventBus interface{}` was removed in favor of this real interface; container_test.go's fake EventBus value (an anonymous struct that no longer satisfies the real interface) was replaced with a real NewBus(). A review pass caught and fixed two correctness issues before completion: (1) `wg.Add(1)` was originally called after Subscribe released its lock, racing a concurrent Close's `wg.Wait()` — a sync.WaitGroup misuse that can panic; fixed by moving Add inside the same locked section as the closed check, with a 200-iteration regression test (TestBus_SubscribeConcurrentWithCloseDoesNotRace); (2) handler panics were originally unrecovered; fixed via deliver()'s recover(), with TestBus_HandlerPanicDoesNotStopOtherSubscribers proving a panicking subscriber doesn't block delivery to a healthy one and that its own goroutine survives to receive the next event. `go build ./...`, `go vet ./...`, `go test ./... -v` clean across all 5 go.work modules (98.9% statement coverage on services/core, 21 new tests covering publish/subscribe, multiple independent listeners, async/non-blocking delivery, buffer-overflow dropping, idempotent unsubscribe/Close, per-event-type isolation, and the two regression cases above); `gofmt -l` clean on both new files (eventbus.go, eventbus_test.go). `go test -race` unavailable in this environment (no cgo toolchain), same constraint noted under SPEC-0005/0007. Built on feature/event-bus.
